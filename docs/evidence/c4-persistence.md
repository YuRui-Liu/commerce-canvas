# C4 persistent canvas and context evidence

2026-10-13; macOS arm64, Apple M5 Pro; Electron 44.7.0 / embedded Node 24.21.0.

## Implementation boundaries

- Migration 004 adds project-scoped canvases and selected-canvas state. Canvas graph, viewport, right-panel drafts, active tab, selected IDs and local user requirements save atomically under an expected storage revision. Node payloads contain asset-version references, not image bytes or full product facts. Asset versions must exist in the same project; unavailable run/definition references are rejected. Canvas references are recorded for asset retention.
- Project facts retain their separate C1 revision. Current project is now persisted as an explicit settings value; the previous bridge test expectation of `null` after restart was advanced to the exact selected project ID. Its cross-project image-access denial assertion remains intact.
- SaveCoordinator separates local edit sequence from database revision. A delayed acknowledgement advances only saved sequence, never replaces the live document or viewport. Saves serialize and coalesce; dragging publishes at gesture end. Failed revisions retain the draft, never silently retry or overwrite. Explicit transient retry still uses the same expected revision. Conflict offers reload or a distinct canvas copy.
- Canvas mounts change only for explicit load ID/epoch. Theme changes and save acknowledgements preserve the graph mount. Project/canvas switches cancel unfinished add batches and flush committed work; ordinary close waits for batch completion. Existing import locks remain active across file imports.
- PanelState is typed and canvas/project scoped. Inspector drafts are keyed by node ID. Saving a requirement snapshots selected node references immediately, then displays the user message only after SQLite confirms it. The UI says execution is unconnected and does not fabricate assistant output or an LLM submission. Credential forms are not part of PanelState.
- Main prevents normal window close and app quit, sends a fixed preload flush request with nonce, and waits for a sender-validated result. Renderer waits for active work, commits pending canvas work, flushes SQLite saves and saves product facts. Main destroys the window/shuts down runtime only on success. Renderer timeout and main 15-second timeout show failure and preserve the window; conflict recovery was exercised. This does not promise persistence after OS force-kill or power failure.
- C3 follow-ups: “商品资料 / 补充商品依据” clear the actual canvas selection so clicking the same node reopens its inspector; project changes clear import results. Both have Electron assertions.

## Quality-review follow-up: hidden-only fault injection

Three Important review findings were reproduced with new hidden Electron regressions before implementation changes: the inspector remained editable during a delayed copy; close after an in-flight product save resubmitted an obsolete revision; and a failed target canvas load left the main process on the wrong project. The initial three-test run failed at exactly those assertions.

- Persistent panel entry points now check the synchronous workspace operation lock; the inspector textarea, context buttons and tabs also visibly disable. Delayed-copy and close/product-save tests invoke a textarea handler captured before locking and prove it cannot change the accepted draft. Internal batch commits still reach the save queue.
- Product save reads the current project/draft/dirty/revision from a ref at invocation, including after the close operation's lock wait. The ref is updated when a save acknowledges and when a project installs. A delayed already-committed update followed by close now performs exactly one project update and closes without a false conflict.
- Project loading prepares project data, assets and canvas before committing the main-process access context or installing target UI state. `prepareProject` no longer selects or installs a canvas; it may create the target project's first empty canvas if none exists. Explicit one-shot failures in both `listCanvases` and `loadCanvas` leave A selected in main/UI, preserve A's image access and editable facts, and allow a subsequent retry to B.

The hidden desktop smoke uses Electron's actual `webContents.getBackgroundThrottling()` getter because `getLastWebPreferences()` does not return that property. All test windows assert invisible and unfocused. Native picker rejection and the explicit replacement path remain exercised.

A separate hidden bridge timeout was reproduced at the final close immediately after the second launch and bridge reads, before React readiness. Preload now installs its fixed flush listener immediately, retains a pending nonce until the workspace callback registers, and will not acknowledge success for a callback that has since unregistered. This covers the interval after preload registration and before React registration, not a promise about requests sent before preload itself exists. Main sender/nonce validation is unchanged. The same bridge case then passed without delaying its final early close. Its pre-fix trace is retained at `apps/desktop/dist/c4-bridge-before-fix-trace.zip`.

The next packaged full hidden run passed 18 of 19 tests; the remaining bridge case reported an A image as loaded after a direct test switch to B. Controlled test-only deferral reproduced the cause: calls were A, a second initialization A, then B; releasing the delayed initialization call left the actual current project A. The protocol correctly served the selected A context, rather than bypassing B isolation. The bridge test now waits for the first workspace's real “本地工作区” ready state before directly mutating bridge context, asserts exact B context after reload, and retains the unchanged denied-image assertion. Its final second-launch early close still has no React-ready wait. Temporary IPC diagnostics and gates were removed after this reproduction.

Verification before the final readiness-only test adjustment: 61 unit tests, typecheck and diff check passed; the minimal hidden bridge/three-race/desktop run passed 5 of 5; all four strengthened race tests and hidden desktop checks passed in the packaged 18-of-19 run.

Final parent verification after removing diagnostics and adding the initial ready condition: the minimal hidden bridge run passed 1 of 1 (session 94177, exit 0); a newly rebuilt packaged app passed the complete hidden Electron suite, **19 of 19 in 23.0 seconds** (session 94294, exit 0). This includes the bridge case in 920 ms, all four race regressions, invisible/unfocused windows, the real background-throttling getter, native-picker denial/replacement, and packaged development-URL isolation. No test window was intentionally shown or focused, and no additional screenshot preview was opened during this follow-up. Final source quality review reported the three Important findings resolved with no new Critical/Important issue; the lifecycle boundary remains the preload-registration scope described above.
